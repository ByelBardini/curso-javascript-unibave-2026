Exercício 01 - Consulta de DDD

Agora com AJAX: o usuário digita um DDD e a página mostra as cidades que usam aquele DDD, sem recarregar. API usada: BrasilAPI, /api/ddd/v1/{ddd}.

  1. Antes de chamar a API, confira se o DDD tem exatamente 2 dígitos numéricos. Se não tiver, avise e nem faça o fetch.
  2. Enquanto espera a resposta, mostre Buscando... no aviso e desabilite o botão (botao.disabled = true), para o usuário não disparar várias buscas. Quando a resposta chegar, dando certo ou não, habilite de novo.
  3. Se a API responder com erro (teste 10), mostre no aviso a message que ela mandou e limpe o estado e a lista que estavam na tela. Se nem houver resposta, avise pelo catch.
  4. Se der certo, mostre a sigla do estado e guarde as cidades no array cidades, que é a fonte da verdade. mostrarCidades(lista) recebe um array, cria um <li> por cidade e escreve Mostrando 12 de 58 cidades.
  5. O campo de filtro usa o evento input: a cada letra, monta um array só com as cidades que contêm o texto digitado e passa para mostrarCidades. O filtro não chama a API de novo, ele trabalha em cima do array cidades, e não pode depender de maiúscula ou minúscula.
  6. Desafio: busque automaticamente assim que o segundo dígito for digitado, sem precisar do botão, e troque a sigla pelo nome completo do estado e da capital com uma segunda chamada (/api/ibge/uf/v1/{sigla}): SC - Santa Catarina (capital: Florianópolis).

    Strings também têm includes(): "ORLEANS".includes("LEAN") é true. As cidades chegam em maiúsculas, então passe o texto do filtro por toUpperCase() antes de comparar. Para conferir: Orleans está no DDD 48.

    Exercício 02 - Controle de estoque

    Agora com a API de Produtos, a mesma da parte 02, que salva de verdade. Leia a documentação antes de começar: as rotas, os campos do produto e os erros estão todos lá. Os produtos ficam guardados no seu código de aluno, que vai na URL.

    1. Guarde o endereço numa constante, com o seu código no final: https://exemplosapi.evolutivasistemas.com.br/api/seu-codigo. O botão inserir exemplos faz POST /exemplos, que cadastra alguns produtos prontos, e depois carrega a tabela de novo.
    2. carregarProdutos() faz o GET em /produtos, ordenado por nome e de 5 em 5: ?ordenar=nome&limite=5&pagina=1. Coloque também &atraso=1000, que faz a API demorar 1 segundo, e mostre Carregando... com os botões de página desabilitados enquanto espera. Os produtos da página ficam no array produtos, que é a fonte da verdade da tabela. A tabela é carregada assim que a página abre.
    3. Paginação: o total de produtos (sem contar a paginação) vem no header X-Total-Count da resposta. Use esse total para escrever Página 2 de 3 (12 produtos) e para desabilitar o botão anterior na primeira página e o próximo na última.
    4. Cada linha tem os botões -1 e +1, que alteram o estoque com PATCH, mandando só { "estoque": novoValor }. Não deixe o estoque ficar negativo (nem chame a API). A resposta do PATCH já traz o produto atualizado: troque o objeto no array e redesenhe a tabela, sem fazer outro GET.
    5. O botão cadastrar faz POST /produtos com nome, preço e estoque. Se a API responder com erro, mostre o erro e, com for...in, cada campo de detalhes (ex.: preco: Campo obrigatório). Teste mandando o preço sem Number() para ver a mensagem da API. O botão excluir de cada linha faz DELETE, que responde 204 sem corpo: confira o status e não chame o .json().
    6. Desafio: parte 2 da API, com login. Com o usuário e a senha que o professor passar, faça POST /auth/login e guarde o token numa variável. A partir daí, todas as chamadas usam https://exemplosapi.evolutivasistemas.com.br/privado no lugar de /api/seu-codigo (os caminhos /produtos e /exemplos continuam iguais) e enviam o header Authorization com "Bearer " + token. Se alguma chamada responder 401, mostre a mensagem da API e peça o login de novo.
